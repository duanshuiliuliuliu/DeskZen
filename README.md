# DeskZen（桌面众生）（暂定）

## 产品定位与核心理念

DeskZen 是一款拥有“独立生活节律”的桌面伴生 AI 软件。
不同于传统的“指令驱动型”桌面宠物或聊天机器人，DeskZen 中的每一个角色（Persona）都是一个“活在屏幕里的室友”。它们拥有自己的作息时间表，会根据当前的状态（吃饭，休息，读书等等，每个角度的生活内容不同）做出相应的行为表现，并能基于环境或时间节点轻度、非打扰式地主动发起对话。用户的交互反馈也会随角色的当前状态而产生差异。

## 核心功能模块与业务逻辑

### 角色与作息系统 (Life Schedule Engine)

这是本产品的核心引擎，决定了角色的行为和回复逻辑。

- 多角色支持 (Multi-Persona)：支持不同性格、物种的角色（如：内卷型程序员猫咪、佛系摸鱼少女等）。
- 状态机驱动 (State Machine)：每个角色配置独立的 24 小时作息时间轴，映射至核心生活状态（State）。
- 状态示例：Sleeping (睡眠), Working (专注工作), Relaxing (摸鱼/发呆), Eating (进食), Playing (自娱自乐)。
- 状态与回复绑定：角色被动接收用户对话时，回复内容受当前 State 严格约束。
- 场景示例：用户在角色“Sleeping”状态下强制对话，角色仅回复简短的起床气或梦话，拒绝进行长篇大论。

### 主动交互与防打扰机制 (Non-Intrusive Proactive Interaction)

角色需要在不打断用户工作的前提下，展现其主动性。

- 气泡与纸条机制 (Bubble & Notes)：主动发起的话题绝不采用系统弹窗或强制焦点夺取。
- 形式：在角色头顶弹出轻量级、带淡出动画的对话气泡；或者在屏幕角落贴一张“虚拟便利贴”。
- 交互：用户可以选择无视（气泡超时消失），或点击气泡/纸条展开对话面板。

## 视觉表现与桌面渲染 (Visual & Rendering)

- 视觉风格（首发/MVP）：2D 像素风 (Pixel Art)，资源成本低、内存占用小；跑通流程后可切换为更精美的 2D UI。
- 透明穿透窗口：无边框透明窗口，角色之外不遮挡桌面（可选整窗点击穿透）。
- 环境贴合 (Environment Snapping)：角色可固定在屏幕边缘，或“站立”在当前活动窗口的标题栏上（规划中）。

## 技术架构

```
┌─ 渲染层（WebView2 + Vite + TypeScript，无框架）─────────────────┐
│ 角色动画（spritesheet + CSS steps）│气泡│悬停状态标签│对话/设置页  │
└───────────────▲───────────────────────────▲───────────────────┘
   Tauri IPC（command / event）               │
┌───────────────┴───────────────────────────┴───────────────────┐
│ Rust 核心进程（常驻，低占用）                                   │
│ 生活状态引擎 │ 气泡调度 │ LLM 网关(DeepSeek) │ 窗口管理 │ 托盘    │
└───────────────▲───────────────────────────────────────────────┘
   Tauri 窗口能力：透明无边框、点击穿透、按需创建/销毁窗口
```

设计原则：

- **逻辑与渲染分离**：所有“活着”的逻辑（状态、时间、气泡、LLM）都在 Rust 主进程，WebView 只负责表现；隐藏/销毁窗口不影响角色状态。
- **按需创建窗口**：对话窗、设置窗在需要时创建、关闭即销毁，避免常驻 WebView 占用内存。
- **配置驱动角色**：角色的作息、状态、动画、气泡、提示词全部来自 persona JSON，加新角色只需新增配置。

## 交互约定

| 操作 | 行为 |
|---|---|
| 按住角色拖动 | 移动角色窗口（移动超过 4px 判定为拖动） |
| 左键双击角色 | 打开对话窗（贴在角色旁边，拖动角色时跟随） |
| 右键点击角色 | 无反应（已禁用 WebView2 右键菜单） |
| 鼠标悬停角色 | 显示当前状态标签 |
| 托盘左键单击 | 角色隐藏时显示角色 |
| 托盘左键双击 | 打开设置界面 |
| 托盘右键 | 菜单：设置 / 显示隐藏角色 / 更换角色 / 退出 |

## 核心流程

### 状态引擎流程

1. 启动时加载 persona 配置（`personas/dog.json`：24 小时时间轴 → 状态，状态 → 动画/气泡/回复约束）。
2. Rust 引擎每 30 秒按本地时间计算当前状态，变化时广播 `state-changed` 事件。
3. 前端收到事件后切换 spritesheet 行（动画）并更新悬停状态标签；引擎同时弹出对应状态的气泡。

### 对话流程

1. 双击角色 → `open_chat`（async 命令，在 Tauri 主线程安全地创建窗口并定位到角色旁）。
2. 发送消息 → 前端把最近 20 条历史一起发给 `chat_send`。
3. Rust 组装 system prompt：**角色定义 + 回复风格 + 当前状态约束**（来自 persona 配置），加上历史消息，调用 DeepSeek `deepseek-v4-flash`。
4. 回复返回后显示在对话窗；发送时角色头顶冒气泡“汪，收到！”。

### 窗口生命周期

- 对话窗、设置窗均按需创建（异步命令），关闭即销毁，WebView2 资源随之释放。
- 注意：Windows 上在同步命令里创建窗口会导致窗口无法响应关闭，因此一律使用 `async` 命令。

## 配置

### LLM（DeepSeek）

配置文件位于 `%APPDATA%\com.deskzen.app\llm.json`：

```json
{
  "base_url": "https://api.deepseek.com",
  "model": "deepseek-v4-flash",
  "api_key": "sk-..."
}
```

也可通过环境变量 `DESKZEN_DEEPSEEK_KEY` 覆盖 Key；或打开设置界面直接填写保存。Key 不会进入前端代码和安装包。

### 角色

每个角色一个 JSON（`src-tauri/personas/<id>.json`），包含：

- `system_prompt`：角色定义、回复风格、各状态下的行为约束（注入 LLM）；
- `states`：状态的中文名、spritesheet 行/帧、气泡文本池；
- `schedule`：24 小时作息时间轴（支持跨午夜）。

## 运行与构建

前置要求：Node.js 18+、Rust stable（MSVC 工具链）、WebView2（Windows 10/11 自带）。

```bash
npm install          # 安装前端依赖
npm run tauri dev    # 开发模式（热更新）
npm run tauri build  # 生产构建，生成安装包（NSIS/MSI）
```

> 注意：不要用裸 `cargo build` 代替 `tauri build` —— 前者是 dev 模式，会去连接 vite 开发服务器，页面无法独立运行。
